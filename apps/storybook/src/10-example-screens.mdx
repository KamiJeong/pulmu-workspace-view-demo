## Screen inventory

Every run shown below comes from an anonymized `@pulmu/model` fixture that has already passed through `adaptPulmuRunContext`. Screen components never receive a raw prompt, branch, log, environment value, commit hash, error message, or pull-request URL.

| Screen | Published design-system components | Contract demonstrated |
| --- | --- | --- |
| Component Map | Every `componentMaturity` export, plus explicit Drawer and Toast gaps | Same canonical composition in scoped Dark (left) and Light (right) themes, audit status distinct from beta API maturity, and responsive parity |
| Workspace Overview | `AppShell`, `CollapsibleSidebar`, `PageHeader`, `MetricGrid`, `MetricCard`, `ContentWithRail`, `ForgeStageRail`, `ActiveStagePanel`, `DataState`, `DataTable`, `Badge`, `Button` | Canonical App Shell, one active stage, nested Pattern, and ready/loading/empty/error/stale data |
| Active Forge Run | `AppShell`, `PageHeader`, `RunLifecycleStatus`, `ForgeRiskBadge`, `TaskMetadata`, `ContentWithRail`, `ActiveStagePanel`, `ForgeStageRail`, `AgentCard`, `AgentGroup` | Seven stages, one active stage, the sole Smith writer, and independent read-only reviewers |
| Quench Retry | Run-detail components plus `RetryLoop` and `VerificationSummary` | Exact `Quench → Hammer → Quench` path and the same Smith correction |
| Hone Review Finding | Run-detail components plus `ReviewFinding` and `RetryLoop` | Blocking finding and exact `Hone → Hammer → Quench → Hone` path |
| Completed Local Delivery | Run-detail components plus `VerificationSummary`, `ReviewFinding`, and `DeliverySummary` | Reviewed local commit with no GitHub pull request |
| Completed GitHub Delivery | Run-detail components plus `VerificationSummary`, `ReviewFinding`, and `DeliverySummary` | Reviewed GitHub pull-request delivery without displaying a raw URL |
| Failed Run | Run-detail components plus `FailureInterruptedNotice`, `VerificationSummary`, and `DeliverySummary` | Failed verification, failure code, and blocked delivery |
| Interrupted Run | Run-detail components plus `FailureInterruptedNotice` and `DeliverySummary` | Session interruption without misreporting a verification failure |
| Run History | `AppShell`, `PageHeader`, `DataState`, `DataTable`, `Badge`, and `Button` | Sanitized lifecycle comparison, focusable narrow-table overflow, loading, and stale data |
| Empty Workspace | `AppShell`, `PageHeader`, `StateLayout`, and `Button` | Quiet first-use state and the single public `$pulmu "<task>"` entry point |

## Responsive, keyboard, accessibility, and visual coverage

- Component Map has bounded Dark and Light header, Data, workflow, and Overlay/gap baselines at 1440px, 768px, 390px, and 320px, avoiding clipped scaled full-page captures. Both themes resolve simultaneously in nested scoped panes; panes stack Dark then Light at 768px and below, and sample groups become one column at 390px and below.
- Workspace Overview is captured in light and dark themes at 1440px, 768px, 390px, and 320px.
- Active Forge Run covers desktop, tablet, mobile, and narrow compositions. Every other workflow outcome has a desktop baseline; Run History adds a focusable 320px table-overflow baseline and Empty Workspace adds a mobile baseline.
- Story play tests exercise the skip link, desktop 44px navigation control, focus-managed compact drawer, one-`h1` rule, valid fragment targets, canonical stage structure, retry paths, delivery distinctions, and page-level overflow.
- Storybook accessibility checks run with `a11y.test: "error"`; Chromium screenshot assertions provide the visual-regression gate.

## Non-goals

These examples do not implement a production backend, live GitHub API, authentication, billing, invitations, Repository Onboarding, multi-tenant organization management, source-file mutation, or deployment. Labels such as Billing, Invite, and Repository Onboarding are intentionally absent from the product navigation and actions.
